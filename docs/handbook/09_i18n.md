# i18n Playbook

Follow these rules when working with translated UI. Locale lives in the **URL** — never in client state.

## When to Use

- Adding a new string or namespace.
- Adding a new locale.
- Reviewing that translated UI doesn't break layout or type safety.
- Building a new route that should be locale-aware.

## 1. Locale Routing (TanStack Router, no library)

- One optional param `{-$locale}` matches `/`, `/en`, `/vi`, ...
- Route `src/routes/{-$locale}.tsx`: `beforeLoad` validates the locale and **redirects unknown locales to `/`** — never throw.
- Shell derives locale from `location.pathname` for `<html lang>` and for components outside the route (404 / error pages).
- Switch locale with navigation, not state:

```tsx
<Link to="/{-$locale}" params={{ locale: "vi" }} />           // → /vi
<Link to="/{-$locale}" params={{ locale: undefined }} />      // → / (default)
```

## 2. Content Organization (per-locale + namespace JSON)

Translations are content data — JSON, one directory per locale, one file per namespace:

```text
src/lib/i18n/
|-- locales.ts        # LOCALES, DEFAULT_LOCALE, isLocale, getLocaleFromPathname
|-- resources.ts      # imports JSON, derives Messages type, enforces vi shape
|-- provider.tsx      # I18nProvider, useI18n (typed t), createT
|-- index.ts          # public barrel
`-- locales/
    |-- en/           # English is the master schema
    |   |-- common.json   # shared UI: nav, search, sign in, footer, toasts
    |   |-- home.json     # home page chrome: hero, features, stack
    |   |-- auth.json     # auth dialog/forms
    |   |-- error.json    # 404 + error fallbacks
    |   `-- dashboard.json# admin dashboard nav & titles
    `-- vi/
        |-- common.json
        |-- home.json
        |-- auth.json
        |-- error.json
        `-- dashboard.json
```

Rules:

- **English is master**: `type Messages = typeof en`, then `const vi = { ... } satisfies Messages` → missing/mismatched `vi` keys fail at compile time.
- **Namespace by feature** (`common`, `home`, `auth`, `error`, `seminars`, `publications`, `projects`), max 2–3 nesting levels.
- **Semantic keys** (`auth.signInError`). Never share one key across two contexts that translate differently.

## 3. Translate UI Chrome, Not Content Data

Translate the interface — navigation, section headings, buttons, CTAs, labels, form fields, errors, toasts. **Keep editorial/mock content in the source language**: publication titles, quotes, card descriptions, feature blurbs stay English even when the UI is Vietnamese. Mixed chrome/content is normal.

## 4. Type-Safe Keys

- Global: `useI18n()` → `t("auth.signIn")` — dotted key validated against `Messages` at compile time.
- **Namespace-scoped** (prefer inside feature components): `useI18n("auth")` → `t("signIn")` — key must exist in the `auth` namespace.

```tsx
const { t } = useI18n("auth");   // t("email") only
const { t } = useI18n();         // cross-namespace: t("common.search")
```

Never cast `key as string` — that voids the guarantee.

## 5. Layout Safety for Long Strings

Localized text is 20–40% longer than English. Do **not** fight flex with `shrink-0`/`min-w-0` tricks on headlines (that turns overflow into squish). Use **locale-aware typography**:

```tsx
// routes/{-$locale}/-components/hero.tsx — one step smaller for vi so it fits the fixed row
className={cn(
	"text-4xl ... sm:text-5xl md:text-6xl text-balance",
	locale === "vi" ? "lg:text-6xl xl:text-7xl" : "lg:text-7xl xl:text-8xl",
	className,
)}
```

- Keep content boxes `max-w-*` and let paragraphs wrap — they always fit.
- Use `text-balance` on large headings.
- If a section can't fit localized text in one row, redesign it to wrap — never overflow or squeeze.

## 6. Adding Content / Locales

- **Add a string**: key in `locales/en/<ns>.json` (master) + matching key in `locales/vi/<ns>.json`. TypeScript enforces parity.
- **Add a locale**: add code to `LOCALES`, create `locales/<code>/` with the same namespace files, register in `resources.ts`.
- **Add a route**: any route under `{-$locale}` is locale-aware; link with `Link to="/{-$locale}/..."` + `params`.
